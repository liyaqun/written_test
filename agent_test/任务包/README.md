在原任务包基础上，补齐了 `rubric.md`、
`verifier/verify.py` 与 `skill/SKILL.md`。

## 一、判断的难点所在

难点在怎么应用规则上，给出的四台设备分别对应四类规则应用陷阱，专业领域人士可能在**条款之间的优先级与覆盖关系**上出错：

| 设备 | 陷阱 | 正确判定 |
|---|---|---|
| SV-001（**题眼**） | 额定上限列为空 → 须回退到机柜级限值 62℃，见空就跳过会漏判 | 需检修(4.1) |
| SV-002 | 温度 66℃ 未超 68℃，但告警 4 次触发 4.2，且「无论温度是否超限」 | 需检修(4.2) |
| SV-003（干扰项） | 温度 71℃ 已超 68℃，但状态「返修中」按 4.3 优先排除 | 不适用(4.3) |
| SV-004 | 额定 75℃ 已列出、实测 78℃ 超限；80℃ 机柜限值仅在额定为空时启用 | 需检修(4.1) |

这四点分别对应不同的陷阱：① 空值回退被跳过；② 覆盖句式（「无论……都」）被忽略；
③ 排除类条款没有优先于数值条款；④ 回退值被错误地用在了非空字段上。Rubric 的判分方向据此
设定：由于第一题较难，所以 SV-001 加权。

## 五、Skill的设计


### 泄漏说明

- skill 全文不含任何具体数字（62/80/68/75/78/3 次/4 次）、设备编号（SV-*）、条款号
  （4.1/4.2/4.3）、机柜名（通用计算机柜/高密度 GPU）。
- skill 中的「空值回退」「排除类规则优先」「覆盖句式（无论……都）」「枚举值一字不差」
  是**对规范类文档的通用阅读方法**，虽然恰好对应本题的四类陷阱，但它们不指向任何
  具体答案；这些陷阱本身就是规则阅读的通用坑，skill 只是提醒「去查有没有这类情况」，
  从未给出「哪台设备、用哪个数、判什么」。

### Gap

预期：skill 主要影响题眼相关判分点 R1/R9/S1（空值回退），对 R5~R8（条款号，简单匹配）
影响不大。运行后结果如下表，

| 判分点 | no_skill 通过率 | with_skill 通过率 | 差异 |
|---|---|---|---|
| R1 (SV-001 判定) | 3/3 | 3/3 | 0 |
| R9 (SV-001 依据) | 3/3 | 3/3 | 0 |
| S1 (SV-001 说明) | 3/3 | 3/3 | 0 |
| 其余 13 条（R2~R8、R10~R12、S2~S4） | 3/3 | 3/3 | 0 |

两组在全部 16 条判分点上均 3/3 通过，差距为 0。

## 六、运行数据与结论

### 运行条数：每组 3 轮（共 6 轮）

理由：判分点均为二值（对/错）、判分对象仅 4 台设备、每条判分点独立，输出的不确定性主要
来自 LLM 采样。3 轮足以把「系统性错误」与「随机抖动」分开——某判分点 3/3 全对或全错可判为
稳定，2:1 或 1:2 则标记为「受随机性影响、结论需谨慎」。单任务 token 成本极低，3 轮在成本
与统计功效间取得平衡；核心结论「skill 是否提升题眼通过率」是方向性的，3 轮若一致即足够。

### 结论

本任务的用例较为简单（仅 4 台设备、判据明确、且缺少真正的「无需检修」正样本），所用的
DeepSeek 模型能力较强，无需 skill 也能稳定答对：no_skill 与 with_skill 两组在全部 16 条
判分点上均为 3/3 通过，差距为 0。

因此在本任务上，有无 skill 的结果完全一致，观察不到
skill 带来的分数提升。这更可能说明任务对该模型已「饱和」，而非 skill 无效；skill 的增量
价值需在更难、更具干扰性的样本上才能体现。

## 七、A 问：哪几条判分点最可能误判一个已做对的提交？

最可能误判「已做对提交」的是 **R9~R12（判定依据）**，其次是 R1~R4（判定）与 R5~R8（条款）。

- **R9~R12**：判据是「判定依据」列须含某关键子串，而该列是自由文本、措辞多样。例如 SV-001
  的正确依据若写成「额定上限空缺，按机柜级限值判定，64 超限」，既不出现 `62` 也没写全
  「机柜+超」以外的关键事实，可能被误伤。**处理**：用「主判据 + 备选判据」的或/且逻辑
  （如 R9 接受 `62` 或 `机柜+超`）放宽匹配；但「完全不给关键事实」的提交判为不通过，
  因为任务书明确要求写「依据的数值」。
- **R1~R4**：精确相等可能误伤「加了注释/括号」的正确判定（如「需检修（尽快）」）。**处理**：
  去空白后精确匹配，仍不接受多余表述——任务书规定「只填这三个之一」，超范围表述本身视为不合格。
- **R5~R8**：不写条款号只写「温度超标」会误伤。**处理**：正则提取 `4.x`（容忍「第/条/空格」），
  但任务书要求写条款号，故不写编号视为不合格是合理的。

## 八、B 问：本版已知但未解决的问题

1. **语义判分未自动化**：S1~S4（判定说明）仍需人工/模型判定，评分无法全自动闭环。
2. **「无需检修」在 gold 中零出现**：四台设备的正确答案是「需检修×3 + 不适用×1」，
   rubric 没有一条判分点能覆盖「正确判为无需检修」的能力——一个永远不输出「无需检修」
   的 agent 无法被本 rubric 抓住。这是 gold 覆盖度的缺口，也是本版最实质的局限。
3. **判定依据判据的残余误判**：或/且逻辑仍可能对「极端简化的正确措辞」误判，R9~R12 的
   「不通过」案例建议人工复核一遍。
4. **样本量小**：每组 3 轮、LLM 随机性大，gap 数值的统计功效有限，只能支持方向性结论。
