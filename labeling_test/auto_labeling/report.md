# 基于大模型的自动打标：谭松波评论语料情感分类

## 一、数据集与任务描述

**数据集**：谭松波老师的酒店评论语料，正负例各 2000 条，属于较小的文本分类数据集。

| 项目 | 内容 |
|---|---|
| 输入特征 | 评论文本（中文，单条评论一段，可含多句） |
| 打标目标 | 情感二分类：`negative`（差评）/ `positive`（好评） |
| 数据规模 | 好评 2000 条 + 差评 2000 条 |
| 标注情况 | 自带人工标签（gold label），可用于评测 |

任务是典型的**单标签文本分类**：给定一条评论，判断整体情感倾向是好评还是差评。我们不用训练集微调，
而是让大模型直接在 prompt 的引导下完成分类（in-context / few-shot）。

## 二、模型与方法

**模型**：`Qwen/Qwen2.5-7B-Instruct`，通过 vllm 推理调用。

**Prompt 设计**：

1. **系统提示**：说明任务、给定类别、并强制输出为机器可解析的 JSON
   `{"label", "confidence", "reason"}`。
2. **few-shot 示例**：给一好一坏两个例子，示范"评论 → 标签"的对应关系和输出格式。
3. 每条评论作为 user 消息 `Text: <评论>` 发送。
4. `temperature = 0`（贪心解码），保证结果可复现。

```
系统：
你是一个文本情感分类助手。请把输入的评论文本分类为以下两类之一。
类别: negative, positive（negative=差评，positive=好评）

规则:
1. 选择唯一最合适的类别。
2. 只输出一个 JSON 对象，不要额外文字，不要代码块:
   {"label": "<negative 或 positive>", "confidence": <0.0-1.0>, "reason": "<一句话理由>"}
3. label 必须严格使用 negative 或 positive。

示例:
Text: "房间很干净，服务也很周到，下次还会再来。"
{"label": "positive", "confidence": 0.95, "reason": "情感倾向明确"}
Text: "隔音太差了，半夜吵得根本睡不着，很失望。"
{"label": "negative", "confidence": 0.95, "reason": "情感倾向明确"}

用户：
Text: <待分类评论>
```

要模型额外输出 `confidence`（置信度）和 `reason`（理由）是有意为之：置信度可用于低置信样本过滤，方便人工审计和错误归因。


## 三、结果分析

对正负例各取 100 条（n=200）运行，结果如下：

```text
=== Evaluation (n=200) ===
Accuracy: 88.00%

Per-class (gold -> pred):
  negative     support=100  precision=0.81 recall=1.00
  positive     support=100  precision=1.00 recall=0.76
```

**1. 整体准确率 88%（176/200），可用但仍有明显偏向。**

**2. 负向偏差**

- 差评召回率 100%：100 条差评全部判对，一条不漏；
- 好评召回率仅 76%：24 条好评被误判成差评；
- 即 **24 个错误全部是"好评 → 误判差评"，没有一条反向错误**。

模型整体偏"差评"。原因是很多好评是"先抑后扬 / 褒贬夹杂"的写法（"虽然…但整体还不错"），
文本里堆着大量负面词（苍蝇、隔音差、房间小、早餐差、服务差），模型容易被这些负面细节带偏，
抓不住"整体仍是好评"的主线；而差评的负面信号更集中、更直白，因此几乎不会漏判。

**3. 做得好的地方：能识别反讽**

```
[OK] gold='negative' -> pred='negative' (conf=0.98)
     text: 住这个酒店实在是太享受了,不仅可以使用五彩缤纷的白毛巾,还可以免费听赏别人KTV包厢里的高音演奏.!!
     reason: 整体为反讽，强调噪音扰民导致无法休息，表达不满。
```

这条是典型的"阴阳怪气"式反讽（"实在太享受""白毛巾""免费听别人 KTV"），模型不但判对为差评，
还在 reason 里直接点出"整体为反讽"。说明模型对语气的理解较深入，不是简单关键词匹配。

**4. 短板：褒贬夹杂的长评论容易"抓小放大"**

```
[MISS] gold='positive' -> pred='negative' (conf=0.95)
     text: 其他都可以,尽管不够5星标准,但还是很干净宽敞,最不能忍受的在度假区吃的自助海鲜晚餐,整个被苍蝇包围了...
     reason: 尽管有干净和海滩优点，但晚餐苍蝇问题引发强烈不满。
```

这条整体是好评，但"苍蝇"的负面细节描写太具体，模型把注意力全放到负面细节上，忽略了
"其他都可以、干净宽敞"的主体态度。这类混合情感是主要失分点。

**5. 置信度不可靠**

判错的那条 MISS，模型给的 confidence 高达 0.95——**它在自己最没把握的地方反而特别自信**。
说明 confidence 与真实正确率没有对齐，"低于某阈值就转人工"的策略直接套用会失效，需要先做置信度校准。

## 五、人工 vs 模型打标对比

| 维度 | 人工打标 | 模型打标 |
|---|---|---|
| 速度 | 每条约 10–60 秒 | 每条约 1–2 秒，可批量 |
| 成本 | 按人时计费，高 | 边际成本近零（模型本地部署） |
| 一致性 | 随疲劳下降，标注员间有漂移 | temperature=0 下极高，可复现 |
| 语义理解 | 深，能懂隐晦语气与上下文 | 较强但浅，易被负面细节带偏 |
| 偏见 | 标注员个人差异 | 继承预训练偏见，存在系统性的"负向偏差" |
| 规模 | 受团队规模限制 | 几乎无上限 |

## 六、改进思路

1. **优化提示词**：加入"若评论褒贬夹杂，按整体倾向判断，不要被个别负面细节带偏"的规则，
   并针对易错样本补充更多 few-shot 例子。
2. **多模型投票 / 自一致性**：对同一样本多次采样（temperature 调高）或换多个模型取多数票，
   用投票分歧度作为更可靠的置信度代理。
3. **置信度校准 + 人工兜底**：先对 confidence 做校准，使其能真实反映
   正确率，再据此把低置信样本转人工复核（human-in-the-loop）。
4. **主动学习**：优先把模型最不确定的样本送人工标注，用最少的人力换最大收益。
